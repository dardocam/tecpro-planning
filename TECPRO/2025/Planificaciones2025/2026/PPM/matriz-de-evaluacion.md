# Matriz de Evaluación Teórica de Saberes Previos

**Nivel:** 7.º año – Técnico en Programación
**Área:** Desarrollo de Software
**Propósito:** Diagnóstico de saberes previos
**Tecnología de referencia:** React Native
**Instancia:** Evaluación teórica previa al abordaje de React y React Native

---

## 1. Propósito de la evaluación

Determinar si los estudiantes poseen los conocimientos conceptuales y las capacidades de razonamiento necesarias para abordar posteriormente el desarrollo de aplicaciones móviles con React Native.

La evaluación no busca comprobar la memorización de definiciones aisladas, sino la capacidad para:

* comprender conceptos;
* interpretar código y estructuras de datos;
* relacionar conceptos;
* analizar situaciones;
* identificar errores;
* seleccionar soluciones adecuadas;
* explicar el funcionamiento de un sistema.

**React y React Native no forman parte de esta evaluación**, ya que constituyen contenidos que serán desarrollados posteriormente.

# 3. Competencia 1 – Programación y resolución de problemas

### Saberes esperados

* Algoritmos.
* Variables y constantes.
* Tipos de datos.
* Operadores.
* Expresiones.
* Condicionales.
* Ciclos.
* Funciones.
* Parámetros.
* Valores de retorno.
* Modularización.
* Manejo básico de errores.

### Indicadores de logro

El estudiante:

* identifica entradas, procesos y salidas de un problema;
* selecciona estructuras de control adecuadas;
* interpreta el flujo de ejecución de un algoritmo;
* reconoce errores lógicos simples;
* comprende el funcionamiento de una función;
* diferencia parámetros y valores de retorno;
* puede descomponer un problema en partes.

### Tipo de situaciones

**Comprensión**

* Identificar qué hace un fragmento de algoritmo.

**Interpretación**

* Seguir paso a paso la ejecución de un código.

**Resolución**

* Determinar qué estructura de control utilizar para resolver una situación.

### Peso

**20 puntos**

# 6. Competencia 4 – Comunicación cliente-servidor

### Saberes esperados

* Cliente.
* Servidor.
* Comunicación de red.
* HTTP.
* URL.
* Endpoint.
* Request.
* Response.
* Métodos HTTP:

  * GET
  * POST
  * PUT
  * PATCH
  * DELETE
* API.
* REST API.
* JSON como formato de intercambio.
* Códigos de estado HTTP básicos.

### Indicadores de logro

El estudiante:

* comprende el modelo cliente-servidor;

* reconoce el propósito de los principales métodos HTTP;

El estudiante deberá interpretar una arquitectura similar a:

**Aplicación móvil → HTTP → API → Backend → Base de datos**

Y explicar:

* quién realiza la solicitud;
* quién la recibe;
* qué información se envía;
* qué información se devuelve;
* dónde se procesan los datos;
* dónde se almacenan.

# 9. Distribución cognitiva

La evaluación debe evitar que la mayor parte de los puntos corresponda a preguntas de memoria.

Se propone la siguiente distribución:

| Tipo de actividad       | Propósito                                        |     Peso |
| ----------------------- | ------------------------------------------------ | -------: |
| Comprensión conceptual  | Verificar comprensión de conceptos               |      25% |
| Interpretación          | Analizar código, datos, JSON, HTTP y situaciones |      45% |
| Resolución de problemas | Aplicar conocimientos para tomar decisiones      |      30% |
| **Total**               |                                                  | **100%** |

Esto permite que un estudiante que haya olvidado una definición puntual pueda igualmente demostrar que **comprende y sabe utilizar el concepto**.

# 10. Criterios generales de evaluación

| Nivel                  | Descripción                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Logro alto**         | Comprende los conceptos, interpreta correctamente situaciones y puede justificar sus decisiones.              |
| **Logro adecuado**     | Comprende los conceptos fundamentales y resuelve situaciones habituales con pocos errores.                    |
| **Logro básico**       | Reconoce conceptos pero presenta dificultades para relacionarlos o aplicarlos.                                |
| **Logro insuficiente** | Presenta dificultades importantes para comprender los conceptos fundamentales y resolver situaciones simples. |

---

# 11. Resultado esperado del diagnóstico

La evaluación permitirá determinar si el estudiante posee la base necesaria para avanzar hacia:

**Saberes previos → Diagnóstico teórico → Diagnóstico práctico → React → React Native → Proyecto móvil**

El diagnóstico no pretende determinar solamente si el estudiante **"sabe o no sabe"**, sino identificar:

1. qué conocimientos están consolidados;
2. qué conocimientos presentan dificultades;
3. qué conceptos requieren refuerzo;
4. si existe una base común suficiente para comenzar el desarrollo de aplicaciones móviles.
